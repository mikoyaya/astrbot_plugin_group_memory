# QQ 群档案 / 群记忆插件

这是一个面向 AstrBot QQ 群聊场景的轻量插件。它只记录 QQ 群消息，不主动回复、不调用 AI，也不自动分析聊天内容。

当前版本的目标是提供可靠的数据底座：机器人收到群消息时，自动保存群、成员与消息基础信息；管理员可以维护成员备注、别名和分层标签，并在 AstrBot WebUI 查看和编辑已记录的成员数据。

## 当前能力

- 仅监听 QQ 群消息，不处理私聊消息。
- 兼容 OneBot/aiocqhttp、QQ 官方机器人和 QQ 官方 Webhook 适配器。
- 自动创建群、成员和空白基础画像记录。
- 保存群号、用户号、昵称、纯文本消息、消息时间和平台信息。
- 使用 `(platform_id, platform_message_id)` 去重；重复消息事件不会重复写入，也不会覆盖群名或昵称。
- 自动将明显的毫秒时间戳转换为 Unix 秒。
- SQLite 短暂繁忙时使用超时与有限重试，数据库工作放在工作线程执行，减少对消息事件循环的影响。
- 支持成员备注、成员标签、基础画像查询、记忆列表/清理和插件内部配置查询。
- 在 AstrBot 插件详情页提供“群成员数据”页面，支持查看、筛选成员，并编辑群内备注和标签。
- 建立群内统一 `member_id`，以便把昵称、别名、关系事件和分层标签归集到同一个群成员身份。
- 自动把昵称记录为 `observed` 来源的别名；管理员可以维护常用称呼、群备注或历史别名，并按置信度解析。
- 对文本中唯一明确的 `@别名` 记录 `mention / observed` 关系事件；不会自动推断评价、夸赞、抱怨、传闻或确认事实。
- 支持人工记录提及、评价、夸赞、抱怨、传闻/转述和确认行为，每条均保存来源成员、目标成员、内容、时间、来源与置信度。
- 标签分为 `confirmed`、`observed`、`reported`、`manual`。人工录入默认为 `manual`，不会因一次聊天或转述自动升级为确认事实。
- 支持人工身份合并。合并不删除或改写历史消息，而是以可追溯重定向把来源身份归到目标身份。

## 当前边界

这不是 AI 群管或自动聊天插件。本版本不会：

- 主动发言、主动私聊或主动搭讪。
- 调用 AI 模型生成画像、摘要或记忆。
- 自动创建复杂关系图谱或可视化网络。
- 从聊天内容自动提取评价、夸赞、抱怨、传闻、确认事实、标签、备注或长期记忆。
- 允许 WebUI 直接修改数据库数据。

数据库版本为 v4。既有 `users` 仍是平台级资料；新增 `members`、`member_aliases`、`identity_merge_history`、`tag_definitions`、`member_tags`、`relationship_events` 仅做增量扩展，不会迁移或删除原有消息、备注和旧标签。旧标签会继续显示为人工维护的 `manual` 标签。

## 安装

### 通过 GitHub 仓库安装

在 AstrBot 插件管理中使用仓库地址：

```text
https://github.com/mikoyaya/astrbot_plugin_group_memory
```

安装后启用插件或重载 AstrBot。

本版本使用 AstrBot Plugin Pages 提供成员数据页面，因此需要 AstrBot `v4.24.0` 或更高的 `v4.x` 版本。

### 手动安装

将整个 `astrbot_plugin_group_memory` 目录放到 AstrBot 插件目录：

```text
AstrBot/data/plugins/astrbot_plugin_group_memory/
```

然后在 AstrBot WebUI 的插件管理中重新加载或启用插件。

本插件仅使用 Python 标准库与 AstrBot API，`requirements.txt` 不需要安装额外依赖。

## 配置

在 AstrBot WebUI 的插件配置中可以设置：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `listen_enabled` | `true` | 是否监听并记录 QQ 群消息。关闭后插件仍可加载，但不会新增消息记录。 |
| `database_filename` | `group_memory.db` | SQLite 文件名。只允许填写 `.db` 文件名，不允许填写路径。 |

数据库保存在 AstrBot 数据目录，而不是代码目录：

```text
AstrBot/data/plugin_data/astrbot_plugin_group_memory/group_memory.db
```

## 数据表

插件启动时会自动创建或补齐数据库表，并迁移到当前 `schema_version = 4`。

| 表 | 当前用途 |
| --- | --- |
| `plugin_metadata` | 记录数据库结构版本。 |
| `groups` | QQ 群基础资料。 |
| `users` | 平台级用户基础资料。 |
| `messages` | 已记录的群消息。 |
| `profiles` | 用户基础画像扩展位；当前只创建空记录。 |
| `relations` | 后续关系网扩展位；当前不自动写入。 |
| `notes` | 群内成员手动备注。 |
| `tags` | 可复用标签定义。 |
| `user_tags` | 群内成员与标签的关联。 |
| `config` | 插件内部轻量配置。 |
| `memories` | 手动长期记忆扩展位；本版支持查看和清理已有记录。 |
| `members` | 群内统一成员身份；每个“群 + 用户”一个 `member_id`，可被合并重定向。 |
| `member_aliases` | 昵称、常用称呼、历史别名和群备注等映射，带来源与置信度。 |
| `identity_merge_history` | 人工身份合并的审计记录。 |
| `tag_definitions` / `member_tags` | v4 分层标签定义与成员关联，保留层级、来源和置信度。 |
| `relationship_events` | “谁对谁说了什么”的关系证据事件，而非最终关系结论。 |

`users` 采用“平台实例 + QQ 号”作为身份。备注和标签额外绑定群，因此同一 QQ 在不同群可以拥有不同的备注和标签。后续若需要保存群名片等成员级信息，可在不改变现有数据的前提下新增 `group_members` 表。

### 成员身份、关系与标签

每个“群 + 平台用户”都有一个内部 `member_id`。解析时先匹配 QQ 号和完全匹配的别名，再提供模糊匹配候选与置信度；候选人匹配度接近时不会自行猜测。

“合并到该成员”用于管理员确认两个历史身份实际是同一人。来源身份会保留以供审计，来源别名会复制为目标成员的 `historical` 别名，来源消息会在成员列表中汇总显示到目标成员。

| 标签层级 | 含义 |
| --- | --- |
| `manual` | 人工修改的资料。 |
| `observed` | 有可追溯消息证据的机器人观察。 |
| `reported` | 他人转述，尚未确认。 |
| `confirmed` | 经过多次验证或人工明确确认的事实。 |

关系事件保留来源成员、可选目标成员、事件类型、内容、时间、来源类型和置信度。事件是历史证据，不会直接覆盖或制造最终关系。

## 群内命令

所有命令只在支持的 QQ 群聊中生效。

| 命令 | 用途 |
| --- | --- |
| `/群档案状态` | 检查插件与 SQLite 数据库是否已就绪。 |
| `/备注 添加 QQ号 备注内容` | 为已有消息记录的成员添加或更新当前群备注。 |
| `/备注 查看 [QQ号]` | 查看当前群成员备注；不填 QQ 号时查看自己。 |
| `/标签 添加 QQ号 标签名` | 为已有消息记录的成员添加当前群标签。 |
| `/标签 查看 [QQ号]` | 查看当前群成员标签；不填 QQ 号时查看自己。 |
| `/记忆 列表` | 列出当前群已有的手动长期记忆。 |
| `/记忆 清理` | 清理当前群所有手动长期记忆，不会删除聊天消息。 |
| `/画像 查看 [QQ号]` | 查看成员的基础统计、备注和标签；不会生成 AI 画像。 |
| `/配置 查看 [键]` | 查看插件内部配置。默认读取 `webui_member_limit`。 |
| `/配置 修改 键 值` | 修改插件内部配置。当前可用键：`webui_member_limit`。 |

示例：

```text
/备注 添加 123456789 负责活动报名
/标签 添加 123456789 活跃成员
/画像 查看 123456789
/配置 修改 webui_member_limit 150
```

成员必须先在当前群发过至少一条被插件记录的消息，才能添加备注或标签。这能避免把其他群的同 QQ 用户误关联到当前群。

## WebUI 页面

重载插件后，进入 AstrBot WebUI 的插件详情页，打开“群成员数据”页面即可查看成员列表。

页面的成员列表会显示真实群号，并展示：

- 群名称或群号
- 成员昵称或 QQ 号
- 已记录消息数
- 最近消息时间
- 当前群标签
- 当前群备注

点击成员姓名可打开详情页，查看 QQ 号、昵称、所属群、消息数、最近消息时间、备注、标签和已有的基础画像摘要。详情页可以：

- 修改当前群内的成员备注。
- 添加新标签。
- 删除已有标签。
- 添加、删除并查看别名、别名来源和置信度。
- 添加、删除并查看分层标签，清楚区分人工修改、机器人观察、他人转述和确认事实。
- 查看关系事件的来源、目标、内容、时间和置信度，并人工新增一条事件。
- 将来源成员合并到目标成员 QQ 号；历史消息不会删除。

备注和标签写入插件 SQLite 数据库；保存后会立即更新列表，刷新 Plugin Page 或重载插件后仍会保留。

页面不直接访问数据库文件；它通过 AstrBot 官方 Plugin Page bridge 调用插件内的只读接口。默认最多展示 100 名成员，可通过群内命令修改：

```text
/配置 修改 webui_member_limit 200
```

支持范围为 1 到 500。页面中还可以按昵称、QQ 号、群号、标签或备注筛选。

### WebUI 测试步骤

1. 确保目标 QQ 群已有成员发送过消息，并等待插件完成记录。
2. 在 AstrBot WebUI 打开插件详情页，进入“群成员数据”。确认列表中的“群”列显示群名称和真实群号。
3. 点击任一成员，确认详情显示 QQ 号、所属群、消息数和最近消息时间。
4. 输入备注后点击“保存备注”，关闭并重新打开该成员，确认备注仍存在。
5. 输入标签并点击“添加标签”；点击标签右侧的关闭按钮删除。刷新页面后确认最终标签状态保持一致。
6. 在“别名与身份”添加一个常用称呼，刷新详情页确认来源和置信度仍存在。
7. 在“关系事件”填写事件内容；确认它以 `manual` 来源出现，且没有被自动升级为 `confirmed`。

## 数据记录规则

每条符合条件的 QQ 群消息按以下规则处理：

1. 读取群号、用户号、昵称、平台、消息 ID、纯文本内容与时间戳。
2. 群或用户不存在时自动创建基础记录。
3. 创建空白 `profiles` 记录，供后续人工或 AI 画像功能扩展。
4. 保存消息纯文本、消息时间和平台消息 ID。
5. 同一平台实例的相同非空消息 ID 只保存一次；重复事件完全无副作用。
6. 没有平台消息 ID 的消息仍会写入，但不能进行平台级去重。
7. 图片、语音等没有纯文本内容的消息保存为空文本，不保存原始平台对象。
8. 有且仅有一个成员能匹配的文本 `@别名` 会记录为 `mention / observed` 关系事件；歧义别名不会自动创建事件。

## 隐私与数据管理

数据库包含群号、用户号、可获取昵称、纯文本消息和人工维护的备注/标签。请只在已获得群管理者和成员授权的场景使用，并遵守适用的隐私和数据保护要求。

卸载或更新插件时，不要直接删除 `data/plugin_data/astrbot_plugin_group_memory/`，否则历史数据无法恢复。需要清理数据时，请先备份 SQLite 文件。

## 常见问题

**插件没有记录消息**

1. 确认 AstrBot 插件管理显示插件已启用且无加载错误。
2. 确认机器人位于目标 QQ 群，消息不是私聊或其他平台消息。
3. 检查 `listen_enabled` 是否为 `true`。
4. 在群中发送 `/群档案状态`，确认数据库已就绪。
5. 检查 AstrBot 日志中是否有数据库路径、权限或 SQLite 锁定错误。

**WebUI 页面没有出现**

确认插件目录内存在 `pages/member-list/index.html`，然后在 AstrBot 插件管理中重载插件并刷新插件详情页。

**无法给成员添加备注或标签**

该成员需要先在当前群发过至少一条已被插件记录的消息。让成员先发一条普通群消息后再执行命令。

## 后续扩展方向

后续版本可在保持现有消息数据不变的前提下增加：群成员表、手动记忆添加/编辑、关系维护命令、可视化关系网、数据导出与受控 AI 辅助。当前版本刻意不实现这些复杂功能。
