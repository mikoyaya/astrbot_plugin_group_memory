# QQ 群档案 / 群记忆插件

这是一个面向 AstrBot QQ 群聊场景的轻量插件。它记录 QQ 群消息，不主动回复、不调用 AI；仅以有界规则从普通消息中生成供管理页查看的内部行为画像。

当前版本的目标是提供可靠的数据底座：机器人收到群消息时，自动保存群、成员与消息基础信息；管理员可以维护成员备注、别名和分层标签，并在 AstrBot WebUI 查看和编辑已记录的成员数据。

## 当前能力

- 仅监听 QQ 群消息，不处理私聊消息。
- 兼容 OneBot/aiocqhttp、QQ 官方机器人和 QQ 官方 Webhook 适配器。
- 自动创建群、成员和空白基础画像记录。
- 保存群号、用户号、昵称、纯文本消息、消息时间和平台信息。
- 使用 `(platform_id, platform_message_id)` 去重；重复消息事件不会重复写入，也不会覆盖群名或昵称。
- 自动将明显的毫秒时间戳转换为 Unix 秒。
- SQLite 短暂繁忙时使用超时与有限重试，数据库工作放在工作线程执行，减少对消息事件循环的影响。
- WebUI 读取使用有界短期摘要缓存：成员列表最多缓存 10 秒、成员详情 20 秒、关系聚合与关系网 5 秒；缓存总量最多 256 项、约 2 MiB，超大响应不进入内存缓存。
- 支持成员备注、成员标签、基础画像查询、记忆列表/清理和插件内部配置查询。
- 在 AstrBot 插件详情页提供“群成员数据”页面，支持查看、筛选成员，并编辑群内备注和标签。
- 建立群内统一 `member_id`，以便把昵称、别名、关系事件和分层标签归集到同一个群成员身份。
- 自动把昵称记录为 `observed` 来源的别名；管理员可以维护常用称呼、群备注或历史别名，并按置信度解析。
- 优先从 AstrBot 消息链的 `At.qq` 读取普通群员 @ 的目标 QQ 号，并记录 `mention / observed` 关系事件；文本别名只作为兼容兜底，不会自动推断评价、夸赞、抱怨、传闻或确认事实。
- 仅因被普通成员 @ 而自动建档的成员显示为“仅被提及”；其首次真实发言或被人工合并到另一身份后会升级为“正常成员”，不会再被后续 @ 降级。
- 自动 @ 事件按“群 + 平台消息 ID + 被提及 QQ”幂等。同一消息的重放或重复 At 组件只保留一条对应成员的观察事件；`@全体成员` 不创建个人档案或关系事件。
- 支持人工记录提及、评价、夸赞、抱怨、传闻/转述和确认行为，每条均保存来源成员、目标成员、内容、时间、来源与置信度。
- 标签分为 `confirmed`、`observed`、`reported`、`manual`。人工录入默认为 `manual`，不会因一次聊天或转述自动升级为确认事实。
- 支持人工身份合并。合并不删除或改写历史消息，而是以可追溯重定向把来源身份归到目标身份。
- 关系事件会按“群 + 规范成员对 + 关系类型”实时聚合，显示数量、首次/最近时间、最后证据和事件来源分布；原始 `relationship_events` 始终完整保留。
- 成员页提供原生 SVG 关系网：中心辐射分层、缩放、平移、节点拖拽、低相关节点折叠和可解释的关系语义展示。

## 当前边界

这不是 AI 群管或自动聊天插件。本版本不会：

- 主动发言、主动私聊或主动搭讪。
- 调用 AI 模型生成画像、摘要或记忆。
- 从聊天内容自动提取评价、夸赞、抱怨、传闻、确认事实或长期记忆；当前自动标签仅限可客观核对的行为规则。
- 允许 WebUI 直接修改数据库数据。

数据库版本为 v7。既有 `users` 仍是平台级资料；v7 增加群内 `member_id` 级别的机器人内部画像，关系聚合仍按需计算，不建立冗余关系聚合表，也不会迁移或删除原有消息、备注、标签、别名或关系事件。旧标签会继续显示为人工维护的 `manual` 标签。

## 安装

### 通过 GitHub 仓库安装

在 AstrBot 插件管理中使用仓库地址：

```text
https://github.com/mikoyaya/astrbot_plugin_group_memory
```

安装后启用插件或重载 AstrBot。

本版本使用 AstrBot Plugin Pages 提供成员数据页面，因此需要 AstrBot `v4.24.0` 或更高的 `v4.x` 版本。

### 手动安装

将整个 `astrbot_plugin_group_memory` 目录放到 AstrBot 插件目录：

```text
AstrBot/data/plugins/astrbot_plugin_group_memory/
```

然后在 AstrBot WebUI 的插件管理中重新加载或启用插件。

本插件仅使用 Python 标准库与 AstrBot API，`requirements.txt` 不需要安装额外依赖。

## 配置

在 AstrBot WebUI 的插件配置中可以设置：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `listen_enabled` | `true` | 是否监听并记录 QQ 群消息。关闭后插件仍可加载，但不会新增消息记录。 |
| `database_filename` | `group_memory.db` | SQLite 文件名。只允许填写 `.db` 文件名，不允许填写路径。 |

数据库保存在 AstrBot 数据目录，而不是代码目录：

```text
AstrBot/data/plugin_data/astrbot_plugin_group_memory/group_memory.db
```

## 数据表

插件启动时会自动创建或补齐数据库表，并迁移到当前 `schema_version = 7`。

| 表 | 当前用途 |
| --- | --- |
| `plugin_metadata` | 记录数据库结构版本。 |
| `groups` | QQ 群基础资料。 |
| `users` | 平台级用户基础资料。 |
| `messages` | 已记录的群消息。 |
| `profiles` | 用户基础画像扩展位；当前只创建空记录。 |
| `relations` | 后续关系网扩展位；当前不自动写入。 |
| `notes` | 群内成员手动备注。 |
| `tags` | 可复用标签定义。 |
| `user_tags` | 群内成员与标签的关联。 |
| `config` | 插件内部轻量配置。 |
| `memories` | 手动长期记忆扩展位；本版支持查看和清理已有记录。 |
| `members` | 群内统一成员身份；每个“群 + 用户”一个 `member_id`，含“正常成员 / 仅被提及”状态，可被合并重定向。 |
| `member_behavior_profiles` | 群内 `member_id` 级别的机器人内部画像摘要、窗口统计、分析节流状态与规则版本；不保存原始消息副本。 |
| `member_aliases` | 昵称、常用称呼、历史别名和群备注等映射，带来源与置信度。 |
| `identity_merge_history` | 人工身份合并的审计记录。 |
| `tag_definitions` / `member_tags` | v4 分层标签定义与成员关联，保留层级、来源和置信度。 |
| `relationship_events` | “谁对谁说了什么”的关系证据事件，而非最终关系结论；自动 @ 事件保留平台消息 ID 和目标 QQ 用于幂等。 |

`users` 采用“平台实例 + QQ 号”作为身份。备注和标签额外绑定群，因此同一 QQ 在不同群可以拥有不同的备注和标签。后续若需要保存群名片等成员级信息，可在不改变现有数据的前提下新增 `group_members` 表。

### 成员身份、关系与标签

每个“群 + 平台用户”都有一个内部 `member_id`。解析时先匹配 QQ 号和完全匹配的别名，再提供模糊匹配候选与置信度；候选人匹配度接近时不会自行猜测。

“合并到该成员”用于管理员确认两个历史身份实际是同一人。来源身份会保留以供审计，来源别名会复制为目标成员的 `historical` 别名，来源消息会在成员列表中汇总显示到目标成员。

成员状态属于单个群内 `member_id`，不影响同一 QQ 在其他群的状态。“仅被提及”表示插件只在普通成员的 `@` 中看到了该 QQ，尚未记录到其真实发言；这个状态不是负面标签，也不会参与事实判断。收到该成员的第一条真实群消息后会自动变为“正常成员”。管理员手动合并身份时，合并目标也会被视为“正常成员”。

| 标签层级 | 含义 |
| --- | --- |
| `manual` | 人工修改的资料。 |
| `observed` | 有可追溯消息证据的机器人观察。 |
| `reported` | 他人转述，尚未确认。 |
| `confirmed` | 经过多次验证或人工明确确认的事实。 |

关系事件保留来源成员、可选目标成员、事件类型、内容、时间、来源类型和置信度。事件是历史证据，不会直接覆盖或制造最终关系。

## 群内命令

所有命令只在支持的 QQ 群聊中生效。

| 命令 | 用途 |
| --- | --- |
| `/群档案状态` | 检查插件与 SQLite 数据库是否已就绪。 |
| `/备注 添加 QQ号 备注内容` | 为已有消息记录的成员添加或更新当前群备注。 |
| `/备注 查看 [QQ号]` | 查看当前群成员备注；不填 QQ 号时查看自己。 |
| `/标签 添加 QQ号 标签名` | 为已有消息记录的成员添加当前群标签。 |
| `/标签 查看 [QQ号]` | 查看当前群成员标签；不填 QQ 号时查看自己。 |
| `/记忆 列表` | 列出当前群已有的手动长期记忆。 |
| `/记忆 清理` | 清理当前群所有手动长期记忆，不会删除聊天消息。 |
| `/画像 查看 [QQ号]` | 查看成员的基础统计、备注和标签；不会生成 AI 画像。 |
| `/配置 查看 [键]` | 查看插件内部配置。默认读取 `webui_member_limit`。 |
| `/配置 修改 键 值` | 修改插件内部配置。当前可用键：`webui_member_limit`。 |

示例：

```text
/备注 添加 123456789 负责活动报名
/标签 添加 123456789 活跃成员
/画像 查看 123456789
/配置 修改 webui_member_limit 150
```

成员必须先在当前群发过至少一条被插件记录的消息，才能添加备注或标签。这能避免把其他群的同 QQ 用户误关联到当前群。

## WebUI 页面

重载插件后，进入 AstrBot WebUI 的插件详情页，打开“群成员数据”页面即可查看成员列表。

页面的成员列表会显示真实群号，并展示：

- 群名称或群号
- 成员昵称或 QQ 号
- 已记录消息数
- 最近消息时间
- 当前群标签
- 当前群备注

点击成员姓名可打开详情页，查看 QQ 号、昵称、所属群、消息数、最近消息时间、备注、标签和已有的基础画像摘要。详情页可以：

- 修改当前群内的成员备注。
- 添加新标签。
- 删除已有标签。
- 添加、删除并查看别名、别名来源和置信度。
- 添加、删除并查看分层标签，清楚区分人工修改、机器人观察、他人转述和确认事实。
- 默认查看关系聚合：成员对、关系类型、`xN` 数量、来源分布、首次/最近时间与最后证据；点击聚合项才按页展开原始证据。
- 从详情页打开“关系网”，或在关系网页搜索中心成员；节点点击查看成员资料，关系线点击查看聚合详情和原始证据。
- 人工新增关系事件；它不会自动升级为 `confirmed`。
- 将来源成员合并到目标成员 QQ 号；历史消息不会删除。

备注和标签写入插件 SQLite 数据库；保存后会立即更新列表，刷新 Plugin Page 或重载插件后仍会保留。

页面不直接访问数据库文件；它通过 AstrBot 官方 Plugin Page bridge 调用插件内的只读接口。默认最多展示 100 名成员，可通过群内命令修改：

```text
/配置 修改 webui_member_limit 200
```

支持范围为 1 到 500。页面中还可以按昵称、QQ 号、群号、标签或备注筛选。

### 关系网规则

关系网只读展示已有的关系证据，不推断事实或自动生成标签。默认以当前成员为中心显示当前群一跳关系，最多 30 个节点和 50 条聚合边；“展开更多”最多增加到 100 个节点和 200 条边。可切换到当前群两跳或整个当前群，并按关系类型和来源筛选。

同一关系按“群 + 规范化后的发起成员 + 规范化后的目标成员 + 关系类型”聚合。人工记录、机器人观察和他人转述不会互相覆盖，而是在同一关系项内显示来源数量。成员合并后，历史事件会归入合并后的规范身份用于聚合；展开证据仍可按页查看对应历史记录的安全展示摘要，SQLite 原文不会被改写。没有明确目标成员的事件不会进入图谱，只保留在成员详情的聚合列表与原始证据中。

关系网页面会把同一对成员的定向聚合边合并为一条双向展示边，避免多条线重叠。中心成员固定在画布中心；最强直接关联成员进入第一层，其他直接关联和高权重两跳成员进入第二层，低相关第三层成员默认折叠。布局按关联权重、最近互动与稳定成员 ID 排序，因此刷新后不会随机跳动。

关系语义仅是**前端基于近 90 天结构化关系事件的保守展示**，不是事实认定，也不会写入数据库：

- `朋友`：双方各至少一条 `praise` 或 `confirmation`，正向事件至少两条，且没有可参与判断的负向事件。
- `互喷`：双方各至少两条 `complaint`，负向事件至少四条，且没有可参与判断的正向事件。
- `普通`：存在双向互动，但未达到朋友或互喷阈值；正负混合时也保守显示普通。
- `待判断`：单向互动、仅提及或证据不足，固定显示弱关系。

前端只让 `manual` 与 `observed` 来源事件改变自动结论；`reported`（他人转述）只作为详情中的辅助理由，不参与结论、强度或最近互动排序。最近互动取可参与判断的结构化事件中时间戳最新的一条，不使用普通聊天、引用或单独转述时间。

初次加载时关系边显示“待判断 · 弱”。当该成员对的每个相关聚合都已读取到 `next_cursor` 为空，或当前页最旧事件早于 90 天窗口时，才视为分析完成并更新为最终文案。为保证长期运行稳定，前端对每个聚合最多读取 3 页、150 条近 90 天证据；达到该安全上限但尚未完成时，仍保守显示“待判断 · 弱”。当前只自动分析中心成员的一跳成员对；两跳和低相关边保守显示待判断，仍可点击查看已有证据。

本轮不会读取普通聊天文本，也不做 AI 情绪、协作、嘲讽或上下文判断。因此 `关心`、`对立`、`冷淡`、`路人`目前只保留颜色映射，不会被前端自动生成。关系理由/人工备注持久化、关心/敌意事件以及自动结论供机器人回复读取，将在后续数据库与后端增量中实现。

### 资源控制与长期运行

SQLite 是唯一的长期数据来源。插件不会把 AstrBot 事件对象、原始消息、原始关系证据页、SQLite 连接或模型结果长期挂在内存中。群消息路径只归一化必要字段并写入 SQLite，不在每条消息上重算关系网或画像。

- 关系聚合和关系网只计算近 90 天的结构化关系事件，并由 SQL 预聚合后逐行处理；单次实时查询最多保留 2,000 个预聚合来源项，避免大群历史造成瞬时内存峰值。
- 成员列表、关系网和聚合项只返回短摘要。关系“最后证据”最多 280 个字符；成员详情中的备注/画像摘要与单条原始证据展示最多 4,096 个字符。SQLite 中保存的原文不会因此被删除或改写。
- 单个成员的别名、分层标签和普通标签各最多返回 100 项；长期记忆列表仅返回最多 1,024 个字符的摘要，避免异常数据撑大页面或命令输出。
- 原始证据仍按页读取，但一个已打开的证据弹窗最多保留 200 条页面节点；达到上限后需关闭并重新打开，避免浏览器 DOM 持续增长。
- 手工修改备注、标签、别名、身份合并或关系事件后，会立即清除相关群的摘要缓存；普通消息统计在成员列表中最长可能延迟 10 秒、在已打开成员详情中最长可能延迟 20 秒，以换取高频群的稳定写入。
- 插件卸载时会关闭数据库接口并清空短期缓存、日志节流状态与页面注册状态。当前版本没有图片识别、向量模型或 GPU 推理，也不会主动占用显存。

未来若接入本地模型或 GPU 功能，应采用按需懒加载、局部变量保存推理结果、`finally` 清理临时对象，并在卸载时释放已加载运行时的缓存；本插件不会主动安装或导入 `torch`。

### WebUI 测试步骤

1. 确保目标 QQ 群已有成员发送过消息，并等待插件完成记录。
2. 在 AstrBot WebUI 打开插件详情页，进入“群成员数据”。确认列表中的“群”列显示群名称和真实群号。
3. 点击任一成员，确认详情显示 QQ 号、所属群、消息数和最近消息时间。
4. 输入备注后点击“保存备注”，关闭并重新打开该成员，确认备注仍存在。
5. 输入标签并点击“添加标签”；点击标签右侧的关闭按钮删除。刷新页面后确认最终标签状态保持一致。
6. 在“别名与身份”添加一个常用称呼，刷新详情页确认来源和置信度仍存在。
7. 在“关系事件”填写事件内容；确认它以 `manual` 来源出现，且没有被自动升级为 `confirmed`。
8. 点击“查看关系网”，确认中心成员固定在画布中心、默认出现一跳关系；拖拽非中心节点不会选中文字，单击节点可打开成员详情。
9. 滚轮缩放、拖拽空白处平移，然后再次单击或拖拽节点，确认坐标仍正确；点击“重置视图”确认恢复默认布局与缩放。
10. 确认低相关成员默认隐藏；点击“显示低相关节点”后展开，收起后相关节点与边一并隐藏。
11. 悬停或点击关系边，确认显示“朋友/互喷/普通/待判断 + 强度”、近 90 天证据数、双向互动、最近互动和关键理由；从详情中的方向聚合入口继续查看原始证据分页。
12. 连续切换关系网中心、刷新关系网并关闭证据弹窗，确认旧请求不会继续向当前页面追加内容；连续加载证据时，页面最多保留 200 条记录。

## 数据记录规则

每条符合条件的 QQ 群消息按以下规则处理：

1. 读取群号、用户号、昵称、平台、消息 ID、纯文本内容与时间戳。
2. 群或用户不存在时自动创建基础记录。
3. 创建空白 `profiles` 记录，供后续人工或 AI 画像功能扩展。
4. 保存消息纯文本、消息时间和平台消息 ID。
5. 同一平台实例的相同非空消息 ID 只保存一次；重复事件完全无副作用。
6. 没有平台消息 ID 的消息仍会写入，但不能进行平台级去重。
7. 图片、语音等没有纯文本内容的消息保存为空文本，不保存原始平台对象。
8. 普通成员 @ 另一位成员时，优先从 AstrBot `At.qq` 取得目标 QQ 号并记录为 `mention / observed` 关系事件；目标尚未发言时也会自动创建其“仅被提及”基础成员身份。仅在消息链没有可用 At 组件时才尝试文本别名兜底，歧义别名不会自动创建事件。
9. 有非空平台消息 ID 的自动 @ 事件使用“群 + 平台消息 ID + 被提及 QQ”去重：同一消息重放或重复提及同一 QQ 不会重复写入；同一消息提及多个不同 QQ 时，每个 QQ 各保留一条事件。`@全体成员` 始终跳过。

## 隐私与数据管理

数据库包含群号、用户号、可获取昵称、纯文本消息和人工维护的备注/标签。请只在已获得群管理者和成员授权的场景使用，并遵守适用的隐私和数据保护要求。

卸载或更新插件时，不要直接删除 `data/plugin_data/astrbot_plugin_group_memory/`，否则历史数据无法恢复。需要清理数据时，请先备份 SQLite 文件。

## 常见问题

**插件没有记录消息**

1. 确认 AstrBot 插件管理显示插件已启用且无加载错误。
2. 确认机器人位于目标 QQ 群，消息不是私聊或其他平台消息。
3. 检查 `listen_enabled` 是否为 `true`。
4. 在群中发送 `/群档案状态`，确认数据库已就绪。
5. 检查 AstrBot 日志中是否有数据库路径、权限或 SQLite 锁定错误。

**WebUI 页面没有出现**

确认插件目录内存在 `pages/member-list/index.html`，然后在 AstrBot 插件管理中重载插件并刷新插件详情页。

**无法给成员添加备注或标签**

该成员需要先在当前群发过至少一条已被插件记录的消息。让成员先发一条普通群消息后再执行命令。

## 自动标签与机器人内部画像

自动画像是按“群 + 统一成员身份”保存的内部资料，不会与同一 QQ 在其他群的记录混用。它只在 AstrBot 插件的成员详情页展示，供管理员核对和后续回复策略使用；不会通过 `/备注`、`/标签` 或 `/画像` 命令在群聊中输出，也不会被当作机器人对用户的台词或事实声明。

- 画像从近 90 天的普通群消息中按规则累积，最多读取最近 500 条消息；不是关系网结论，也不依赖最近 50 轮记忆。
- 首次在近 90 天达到 12 条消息后生成；之后至少新增 6 条消息且距上次分析 6 小时才重算。打开成员详情时，未生成或超过 24 小时未更新的旧记录会惰性刷新。
- 当前规则仅生成可客观核对的 `持续互动`、`高频互动`、`爱提问`、`常发图片`、`常发表情包` 标签，并以 `observed / observed` 标明机器人观察来源。人工备注、人工标签和旧版标签不会被覆盖。
- 图片/表情仅识别适配器保留的明确占位标记。当前不会做 AI 情绪、复杂语义、协作、讽刺、上下文分析，也不会自动生成“友好、冷淡、对抗、调侃、熟络”等结论。
- 关系网继续只保存人与人之间的关系证据。本版本没有主动回复或机器人消息写入链路，因此不会把机器人回复放入 `relationship_events`。

`member_behavior_profiles` 只保存摘要、窗口统计、待分析计数、更新时间和规则版本，不复制原始聊天文本或 AstrBot 事件对象。自动标签在下一次合格分析时更新，因此 WebUI 中会标为只读的“机器人观察 / 规则版”。

## 后续扩展方向

后续版本可在保持现有消息数据不变的前提下增加：群成员表、手动记忆添加/编辑、关系维护命令、可视化关系网、数据导出与受控 AI 辅助。当前版本刻意不实现这些复杂功能。
